Four controls, many selectable flavors

The experiment should decide which editing operations deserve first-class controls. It should not mistake values inside those controls—group labels, icons, or arrowheads—for separate product capabilities.

Primitive test: if two constructs are selected, moved, edited, nested, and deleted in the same way, they are one control with a property selector—not two features.

Actual MVP surface

Build these controls once

01 · canvas object

Actor

One uniform actor control. Meaning comes from a readable label and an icon slot, not a hardcoded UML taxonomy.

Identity
Stable ID and display label.
Icon
Qualified, version-stable icon ID such as collection:name.
Order
Horizontal position among actors.
Attachments
Zero or more pills.

02 · timeline object

Connection

One arrow control with endpoints and text. Solid, dashed, open, synchronous, asynchronous, and future arrowheads are flavor choices added during visual polish.

Endpoints
Source and target actor; equality creates a self-connection.
Label
Human-readable interaction text.
Arrow
A visual/semantic style value, not a new primitive.
Attachments
Zero or more pills.

03 · structural object

Group

One nestable container with a type selector. loop, opt, critical, par, alt, break, ref, and custom labels share the same editing control.

Type
Preset or custom value controlling header and presentation.
Label
Readable condition, purpose, or reference.
Sections
One by default; add branches when needed.
Children
Connections and nested groups.

04 · cross-cutting attachment

Pill

A compact visible tag whose detail appears on hover or keyboard focus. It replaces diagram notes without forcing annotation text into the sequence layout.

Tag
Short visible text such as comment or critical.
Detail
Tooltip text after the first colon.
Anchor
Actor or connection in MVP; model can remain extensible.
Multiplicity
Multiple pills preserve source order.

What the study does tell us

  • Actors and connections are unavoidable.
  • A generic group is central: 86 diagrams used at least one grouping across all ten domains.
  • Sections are part of the group control: 76 diagrams needed alternative or parallel branches.
  • Observed frequencies can order presets in menus and choose defaults.

What it cannot decide

  • Whether loop deserves support but critical does not; both are group values.
  • How many icons or arrowheads eventually belong in their selectors.
  • Whether pills matter: the prompt suppressed optional clutter and PlantUML lacks this compact attached primitive.
  • The direct Interview Harness need is sufficient product evidence for pills, without making the library IH-specific.

New syntax primitive

Pills are attached metadata, not free-floating notes

The visible tag stays compact; the detail is available as a tooltip. The library treats tags as arbitrary text and exposes stable pill IDs and events, allowing embedding products to attach their own workflows.

Source sketch

actor API ((comment: any text))
actor Worker

API -> Worker: start job ((critical: something else))
Worker --> API: completed

Parsing rule

pill       := "((" tag ":" detail "))"
actor      := actor-declaration pill*
connection := arrow-expression pill*

Pill {
  id: string
  tag: string
  detail: string
}
  • The first colon separates the visible tag from tooltip detail; later colons remain part of the detail.
  • Pills are selectable, keyboard reachable, editable, reorderable, and removable through one shared inspector.
  • A comment pill is ordinary document data. The host may associate it with a review thread, but the core package does not know about interviews or comments.
  • Free-floating PlantUML notes remain unnecessary for MVP because pills cover compact attachment and the host covers long-form discussion.

Canonical document model

Keep the schema open where the UI is a selector

Core AST

Document {
  actors: Actor[]
  rows: (Connection | Group)[]
}

Actor {
  id: string
  label: string
  icon?: QualifiedIconId
  pills: Pill[]
}

Connection {
  id: string
  from: ActorId
  to: ActorId
  label: string
  arrow: ArrowStyle
  pills: Pill[]
}

Group {
  id: string
  type: string
  label: string
  sections: Section[]
}

Late-bound catalogs

Icons
The document stores a qualified stable ID. The renderer receives an icon resolver; the editor can lazy-load a searchable catalog separately from core.
Arrows
The schema stores an arrow style. Exact tokens, heads, line patterns, and selector order are finalized after the base editor works.
Groups
The model accepts a string type. The editor offers friendly presets plus a custom value, so new labels do not require schema changes.
Pills
Tags are open text. Hosts may layer meaning on recognized tags without changing portable diagram data.

The real MVP boundary

Defer different controls, not cheap selector values

Include now

  • Actor add, remove, rename, reorder, icon selection, and pill attachment.
  • Connection add, retarget, relabel, reorder, self-target, arrow selection, and pill attachment.
  • Generic group create, type, label, section add/remove, nest, move, resize/reparent, and delete.
  • Bidirectional canonical text editing with stable IDs, diagnostics, undo, and redo.

Defer as genuinely different controls

  • Timeline marker: a gap, phase divider, or elapsed-time row. Three corpus diagrams used one.
  • Lifeline span/state: activation or creation/destruction intervals tied to row ranges. Five diagrams used one.
  • Cross-diagram navigation: references with actual link behavior belong to the host contract.
  • Free placement: arbitrary coordinates, floating notes, and decorative shapes would create a different editor.

Revised implementation order

Build by interaction topology

01

Model the four controls

Freeze actor, connection, group/section, and pill schemas with stable IDs and source spans. Keep icon, arrow, group type, and pill tag values open.

02

Ship one baseline rendering

Uniform actors, one arrow, one group appearance, and pill tags. Prove layout, selection geometry, text synchronization, and nesting before growing catalogs.

03

Complete WYSIWYG operations

Add, move, reorder, retarget, wrap in group, add section, reparent, attach pill, edit, delete, copy/paste, undo/redo, and keyboard navigation.

04

Add the icon resolver and picker

Choose a version-pinned public collection, persist qualified IDs, keep the renderer resolver-based, and split the searchable catalog from the lightweight runtime.

05

Polish selectors

Add the generous group preset list, arrow styles, icon search/categories, defaults informed by the corpus, and graceful fallbacks for unknown values.

06

Evaluate new control families

Only after the core is usable, test whether timeline markers or lifeline spans solve real editing needs that cannot be represented by groups, connections, or pills.

Bottom line

The small product is not the one with few labels

It is the one with few interaction models. Actors can carry many icons, connections can carry many arrow styles, and groups can carry many type labels without making the editor conceptually larger. Pills add one compact, reusable attachment model and eliminate the need for free-floating notes.
